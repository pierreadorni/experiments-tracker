## Outcome and harness boundary

Prove the exact T1.6c mixed-role matrix through the engine, not a toy queue or
fabricated pool state. Use real temporary SQLite, standard commands, T1.2b fakes
and event gates. Retain source/action/thread/turn identities and record every
external begin/reply/interrupt/readback/close by slot and process generation.
Unknown results never permit a duplicate turn or replacement action.

The T1.2b fixture intentionally permits one slot only. Extend via a separate
multi-slot fixture, not by weakening that assertion: a per-test no-argument demo
fake class/factory shares one explicit external backend across all cloned slots,
while each connection has a distinct generation. Assert all agents are synthetic;
no clone can instantiate real CodexAgent or start an MCP/socket runtime. Reuse the
clock/task-handle driver, extending its awaited-handle set to the actual research,
supervisor, conversation/Autopilot and pool-registry tasks, deduplicated by task
identity. Include intentionally gated tasks without fixed yield/tick counts or
timed sleeps. Advancing fake time beyond lane reconnect deadlines may restart a
connection; expect a new generation without declaring its remote turn ended.

Use a's production start-counter/generation value for routing assertions; also
log the fake instance ID and independent fake start count and compare them.
Do not inject a fake-chosen generation directly into the registry and then claim
routing was proved. Exercise the production generation path using a stub transport
where necessary to keep counter behavior separate from the fake's own log.

## Coordinator matrix

Take setup call/action counts only after required planning, preparation and
completed-report setup. Zero-turn claims mean zero *additional* turns after that
baseline. Create valid role-source records through their normal commands/engine
transitions; a direct row fixture must be identified and cannot prove dispatch
integration by itself.

Add a fresh-binding-denial case: the cached selection filter admits, session setup
waits, then quota/control revision changes before binding. Assert no begin,
released never-sent claims and pending source state. This tests b's actual last-
moment authority boundary, not merely quota denied at initial selection.

Name source and origin in every project case: research uses `autopilot_actions`
created by ResearchController; supervisor/owner project work uses `project_turns`
from project commands. Weekly synthesis means supervisor priority plus plenty;
non-weekly owner requests mean conversation priority. Do not substitute owner
project chat for the weekly supervisor-overlap case.

Use both same-project experiment/project roles and unrelated projects where valid
under the approved owner-key design. A project role and an experiment in its project
must not be mislabeled as the same logical owner if b uses typed keys. Test the
actual selected policy rather than a configurable test-only bypass.

Lost-turn adoption is not invented for project source tables if T1.4b only
supports `agent_actions`: in that case assert retained uncertainty/no duplicate
and exercise existing role-specific readback where exact IDs are available.
No test may call a new turn a successful recovery merely because the old result
was unreadable. For session shrink, distinguish logical reservation retention,
live configured connection count, and b's conservative remote-turn capacity.
Received results block their owner but consume no turn capacity; pending/terminal
rows also consume none. With debt exceeding a shrunken one-slot configuration,
assert no new begin, no hidden server, and working exact readback until outcomes
settle. The owner must accept this policy before implementation.

## Proposed bounded split

The full matrix plus multi-slot fixtures may exceed a single M card. Propose:

- **T1.6c-1:** shared-backend multi-slot fake factory, production/fake generation
  logs, real pool/role-task driver extension, three overlap cases, reduced one-
  slot and cross-role same-owner cases. If fixture code exceeds ~200 lines, move
  one-slot/same-owner cases to c-2 rather than weaken them.
- **T1.6c-2:** lost begin/restart at equal count AND 2→1/debt two, unreadable result
  plus independent-owner progress when capacity remains, readback at zero capacity,
  and callback/answer routes including late old-generation events.
- **T1.6c-3:** fresh-binding denial, quota interruption across occupied slots,
  shutdown with every slot occupied for experiment AND project roles.

Each stays below 500 changed source/test lines, with focused tests and a green
full suite. Keep detailed existing recovery tests until equivalence is proved.
Do not remove safety coverage or source behavior merely to offset harness lines.
If a scenario reveals an implementation gap, report/fix it through the owning a/b
card scope; no new schema, reason or configuration without the card/owner contract.

## Validation

For every matrix row inspect saved source/owner/action/thread/turn IDs, per-slot
external-call logs, simultaneous live gates where overlap is required, and absence
of forbidden duplicate calls. Test failure diagnostics deliberately so a timeout
cannot silently pass. Run focused scenarios, existing lane/role recovery tests,
Ruff lint/format and the full Python suite outside restrictive subprocess
sandboxes. This is synthetic evidence only; no live Slurm, managed-account,
hosting or phone acceptance follows.
