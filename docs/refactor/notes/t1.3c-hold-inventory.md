## Existing projection and reader surface

`Store.experiment` decodes the saved row, and `Store.projection` currently returns
that stored `hold_reason` unchanged; it does not query `obligations` or other
hold sources. `Store.emit` writes an event/outbox revision but does not calculate
the public projection here. The watchdog (`watchdog.STUCK_SQL`) selects
`experiments.hold_reason`, excludes the current fixed owner-hold allowlist, and
uses no live action/job/transfer plus age as its heuristic; `engine_watchdog`
deduplicates `engine_stuck` notices by `(experiment, reason)`. CLI list/status,
workflow control, and autopilot admission also read the stored field.

Raw reason-dependent SQL/read gates are concentrated in:

- `workflow.recover_terminal_actions` (`agent_recovery_exhausted`) and
  `repair_failed_experiments` (`compute_failed`, `validation_failed`,
  `automatic_repair_pending`, `resources_unavailable`); repair control also
  branches on `automatic_repair_pending` and `resources_unavailable`.
- `workflow.advance` / admission / observation: blocked/error early exits,
  steering restart, submission uncertainty, compute pause/busy, scheduler and
  remote-transfer admission, resource failure, accounting wait, cluster and
  executor availability, plan review, implementation blocked, agent dispatch,
  quota, workspace and project busy states. The direct SQL clear in job
  observation has an explicit reason allowlist.
- `workflow.reconcile_agent_output`, `Store._resume_blocked`, and
  `Store.command`: agent recovery/implementation holds, session retry, retry
  admission, compute/validation repair, request/plan-review decisions, and
  steering restrictions.
- `legacy_archive_actions` preserves `legacy_contract_archived`;
  `Store.update` preserves that value on archived rows and drops phase changes.
- `watchdog`'s fixed owner allowlist controls notification timing. This list is
  an operational policy reader, not a presentation-only consumer.

Also inventory the similarly named but distinct fields before implementation:
`discussions.hold_reason` is per-message, `project_turns.hold_reason` is
project-scope, `autopilot_runs.hold_reason` is run-scope, and
`autopilot_stage_holds` is per experiment/stage/attempt. They are not the
experiment column and must not be silently folded into this experiment mapping.

## Responsibility and source identity questions for design

- **Exact-source waits:** action/thread/turn, scheduler job intent and ID,
  transfer ID, owner request ID, plan-review generation, report request/version,
  steering request/cancellation identity, and saved timer/wakeup ID/due time
  have existing identities. Ownership and waits should follow those saved rows
  transactionally; uncertain external outcomes continue to require exact
  reconciliation.
- **Lifetime advancement:** a nonterminal experiment may have no pending source
  row because the backend has not yet serviced a transition, is between gates,
  or failed to start an eligible next phase. T1.3b rollout requires a persistent
  backend `reconcile` obligation targeting the experiment for this execution
  lifetime, held through source handoffs, with wait naming the saved blocker or
  `none`; it closes on terminal/archive. It must not be refreshed on every tick.
- **Owner state versus work state:** `pause_agent`, `pause_compute`, fresh quota
  admission, `pending_request`, review state, and notices are control facts. The
  reader mapping must decide which are represented by owner obligations versus
  compatibility presentation, while existing inbox notices remain deduplicated
  and actionable. `needs_attention` needs the actual saved pending-request or
  owner-notice identity; an error string alone is not a source.
- **Computed compatibility:** a conservative derived `hold_reason` is a
  projection of saved open obligations through an explicit allowlist to existing
  reasons. It must not infer a reason from owner priority, arbitrary detail, or
  an empty obligation set. Keep terminal/archive presentation and old read-only
  schema behavior intact. Read source and obligation state under the same
  transaction/lock. This inventory does not decide cache versus pure computed
  field or the final precedence for legacy rows.
- **Evidence before a call-site design:** enumerate every distinct string and
  read/write path from the stabilized tree; link each hold to an exact source or
  lifetime advancement; determine which path already emits an event/outbox in
  its mutation transaction; test all readers including watchdog, repair,
  cancellation/archive, and public/gateway projection; preserve existing
  archive and terminal tests. Confirm no C2 activation occurs before complete
  T1.3b source/backfill coverage.
