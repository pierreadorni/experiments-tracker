# T4.7: contract-4 pilot acceptance

Owner permission to run the pilot is separate from readiness. Do not start it
while submission is disabled, and do not use a contract-3 run as substitute
acceptance. Releasing source does not install it on an existing executor.

## Before the pilot

1. In an isolated checkout, pass locked Node 24 `make check` and complete the
   existing synthetic demo. Separately run the contract-4 scripted scenario:
   exact owner approval → one local job → registered result → ready report →
   completed experiment. Check refusal before approval, after a changed objective,
   and during pause; inject a lost submission response and verify exact adoption
   without a second submit. Verify a healthy job does not wake the agent.
2. Use a dedicated owner-approved project and a fresh isolated state directory on
   verified retained local storage. Confirm host placement, a compute-visible
   output root, backup destination, private loopback access, and the per-project
   `research_loop` opt-in. Do not enable it on unrelated projects, change the
   default, or upgrade/restart an existing owner to run this pilot.
3. Confirm supported managed sign-in and fresh explicit quota admission, plus
   local Slurm account/partition/QoS authorization. Use a tiny generated-data CPU
   comparison, with at most one job, one CPU, no GPU, and a short wall limit
   within local policy. Do not enable automatic integration or Autopilot for the
   pilot. An API-billed fallback is not allowed.

## Evidence and stopping conditions

Record the exact source version, isolated runtime/state scope, approval/intent/
job/turn identities, turn and input/output token counts (where reported), owner
interventions, and report readiness in the private installation receipt. Keep
scripted fault injection separate from observations of the live run; do not
manufacture a lost response against live compute to prove the test again.

Stop further dispatch if identity, admission, permissions, or report provenance
cannot be established. Preserve state and reconcile the saved identities; do not
retry or cancel unrelated work. Confirm report and exact terminal job accounting
before stopping the isolated owner. Success does not authorize T4.8 activation:
contract 3 must first drain, with archived readers and exact settlement retained.
