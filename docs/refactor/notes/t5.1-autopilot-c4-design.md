## 1. Current state

Autopilot today is a second engine beside C4. It has its own run lifecycle, its
own project-turn dispatcher, readback and input handling, its own MCP server, its
own wake queue and its own stage-level GPU admission. C4 uses it in two places:
the compute-authority check at submission and the orchestrator objective
approval from T4.4.

## 2. Target (C8)

One engine. The Autopilot lead is a C4 research session, and the policy is data
checked where work is admitted.

- **Lead session = a C4 experiment** in the project (**OWNER 1**). Activating a
  run creates it with the deterministic id `uuid5("autopilot-lead:" + run_id)` and
  a contract marker `contract.autopilot_lead = {"run_id": …}` (**OWNER 2**). Its
  brief is the policy subject, scope, exclusions and instructions. It reuses
  `agent_actions`, exact dispatch/readback/settlement, `agent_wakeups` with the
  60 s debounce, checkpoints and rotation, `ask_owner`, `update_report` (the
  weekly report is the lead's working report), steering, the integration branch
  and the obligation watchdog. No new table: run state stays in `autopilot_runs`,
  and the lead's turns snapshot `run.control_revision` into the existing
  `agent_actions.autopilot_control_revision` column.
- **Lead tools** (served by the existing experiment MCP bridge when the contract
  carries the marker; compute tools `submit_job`, `cancel_job`,
  `register_result`, `register_figure` are not served to the lead):
  `project_status()` (members, calendar, budget view, pending objectives, bounded),
  `create_experiment(request_id, brief, purpose, estimated_finish_at)`,
  `message_experiment(request_id, id, text)` (C4 steering),
  `control_experiment(request_id, id, defer|resume|abandon, reason)`,
  `request_integration(request_id, id, reason)` (C6 queue; respects per-project
  approval opt-in), `update_document(request_id, name, base_version, text,
  sources?)`, `approve_experiment_objective(...)` (T4.4, **OWNER 4**), plus the
  shared C4 `save_checkpoint`, `update_report`, `ask_owner`, `cluster_info`.
  Receipts stay in `autopilot_requests` with author `agent:<agent_action_id>`.
- **Policy as data** (`AutopilotPolicy` schema 1 is unchanged, so saved policies
  still validate; unused fields are ignored, not removed). One module
  (`autopilot_policy.py`, later `autopilot/policy.py` per C11) holds the checks,
  each applied at one admission point:

| Rule | Where it is enforced |
|---|---|
| Run status, start/handoff, writing-phase scope, deferral | `member_authority()` at C4 `submit_job` admission, member turn admission, title turn (existing `authority`) |
| Calendar window, `max_open_experiments` (lead excluded, **OWNER 10**), writing-phase purpose | `create_experiment` |
| Approval envelope | `approve_experiment_objective` + `autopilot_approval.approved` at admission |
| Subscription reserves | `AgentPool` quota for lead and member turns (`decide_policy`) |
| GPU-week budget | C4 GPU admission, when enabled (**OWNER 7**, T5.1g) |

- **Wakeups.** The lead wakes on member terminal phase, member approval
  requests, member ready report, run `message`, calendar boundaries, weekly report
  and handoff deadline. `tick` keeps the idempotent `autopilot_transitions`
  insert to detect boundaries, then records a lead wake instead of an
  `autopilot_inputs` row. This needs one new `agent_wakeups.reason` value,
  `project_update` (**OWNER 3**); scheduled reviews use the existing
  `research_timer` via `next: timer:<s>`.
- **Foundation documents optional.** `update_document` writes
  `autopilot_documents` versions (existing gateway publication). The fixed name
  set stays because the Worker validates it (**OWNER 6**). There is no
  foundation, backlog or handoff gate. The lead's `done` with a ready report sets
  the run to `handoff_ready`; the backend deadline handoff remains.

## 4. Interactions

- **T6.3 (backend binding).** The lead becomes an experiment, so it receives
  `contract.agent` at creation like any member, and Autopilot's special session
  options (`approval_policy="never"`, project `runtime_config`, the
  `autopilot_actions` backend field) go away. The T6 note's "Autopilot project
  server follows the same pattern" item disappears with T5.1e. Whichever lands
  second rebases: if T6.3 is first, T5.1b binds the lead with the project default
  backend and `policy.model`/`reasoning_effort`. Reserves (`decide_policy`) are
  Codex windows; T6.4 must translate them for a Claude spend ledger (**OWNER 9**).
- **Live installation.** Executor-only cards (a–e, g) ship through the normal
  owner-authorized executor update. Card e changes the running engine and needs
  fresh evidence that no `autopilot_actions` row is `pending/dispatching/running/
  uncertain/received` (extend `drain_inventory.py`; owner runs it), and a decision
  on active runs (**OWNER 8**). The hosted Worker stays unchanged if the view
  shape and command kinds are kept. Card f (UI) changes the built web assets and
  needs an owner-authorized Worker/asset publish. No live Slurm or model call is
  part of acceptance; a live Autopilot pilot is a separate owner card.
- **T5.2** later folds D1 `autopilot_*` into generic projections; T5.1 leaves D1 alone.

## Open owner decisions

1. **Lead representation.** Lead is a C4 experiment in the project (recommended:
   one engine, no new tables), or keep `autopilot_actions` with a ported C4
   prompt (a second dispatcher stays).
2. **Lead marker.** `contract.autopilot_lead.run_id` in the saved contract plus
   deterministic id (recommended), or an additive `autopilot_runs.lead_experiment_id`.
3. **New wake reason** `project_update` in `agent_wakeups` (recommended; one value).
4. **Objective approval.** Keep the T4.4 lead tool (recommended) or let the
   backend approve automatically when the envelope admits.
5. **Dropped tools.** Drop backlog, decision, borrowing, foundation, priorities,
   schedule, handoff and `compile_manuscript` for new runs (recommended; borrowing
   becomes an owner policy revision, the paper stays a `paper.tex` document).
6. **Document names.** Keep the fixed set the Worker validates (recommended), or
   relax it with a Worker change.
7. **GPU-week budget.** Defer until C4 GPU admission is enabled (recommended);
   C4 stays CPU-only.
8. **Active runs at cutover.** After drain evidence, create the lead for each
   active run on startup, seeded with `central_argument`/`uncertainty` as its
   first checkpoint, without replaying old turns (recommended); alternative:
   require the owner to stop runs first.
9. **Reserves on Claude.** Map `five_hour_reserve`/`weekly_reserve` to a fraction
   of the Claude spend budget in T6.4 (recommended), or refuse Autopilot on Claude.
10. **Open-experiment limit** excludes the lead (recommended).

## Risks

Re-keying the T4.4 approval proof touches reviewed identity logic (old proofs
must still verify); the lead experiment must be filtered out of research
limits, lists and the watchdog's compute view; cutover with an uncertain saved
project turn would lose its reconciler, so e is gated on drain evidence; saved
`AutopilotPolicy` rows must keep validating.
