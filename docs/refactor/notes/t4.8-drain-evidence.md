# T4.8: source map for drain evidence

This note complements [the rollout sequence](t4.8-rollout.md): it identifies the
current authorities and the minimum read-only evidence needed before engine
retirement. It is not a live inventory, activation approval, schema proposal, or
replacement for an owner-authorized installation review.

## What can still write contract-3 state

A saved C3 experiment is selected from its persisted
`contract.execution_contract`, not inferred from its current project setting.
`Store.command()` in `src/experimenttracker/store.py` still creates C3 by default
when `research_loop_for()` does not select C4, and seeds its `plan`, `prepare`,
`interpret`, and `publish` stages. C4 has a separate research-session path. The
hosted create request is not contract-bound: `gateway/src/index.ts` queues the
payload and a `waiting()` projection with placeholder C3; the executor chooses
contract at local application. See [create compatibility](t4.8-create-compat.md)
for that unresolved delayed-command boundary. Changing defaults alone cannot
prove old C3 records or queued creates have drained safely.

Current C3 engine/write seams include:

- `Workflow.tick` / named `step_*` methods and `advance()` in `workflow.py`;
  planning, implementation, iteration, stage output and validation writers in
  `iteration.py`, `early_repair.py`, and `workflow.py`;
- stage agent dispatch/results and their persisted identities in `workflow.py`,
  `controller.py`, `agent_pool.py`, `codex_client.py`, and `agent_actions`;
- scheduler submit/observe/recovery and saved `jobs` in `workflow.py`,
  `resolver.py`, `legacy_archive.py`, `slurm.py`, `remote.py`, plus
  `execution_transfers` / `output_refs`;
- owner mutations that resume or replace C3 stages (`answer`, plan review,
  steering, retry/repair) in `Store.command()` and `gateway/src/index.ts`;
- numerous `hold_reason` writers across `workflow.py`, `store.py`, `steering.py`,
  `iteration.py`, `early_repair.py`, `cancellation.py`, and `autopilot.py`. T1.3c
  explicitly defers their conversion: these are operational C3 engine state, not
  an independent drain authority, and retire with that engine.

The existing archive boundary is narrower than deletion: `legacy_archive.py`
defines supported contracts `(3, 4)`; `Store.archive_legacy_experiments()` archives
other unfinished contracts. `legacy_archive.settle_job()`, turn/action settlement,
startup/tick archive sweep, and Store/Worker refusals preserve frozen historical
identities. They do not yet archive C3, and must not be confused with the later C3
retirement boundary.

## Existing evidence authority and gaps

- `status` in `cli.py` opens SQLite with `mode=ro`, but returns only experiment ID,
  phase, hold, updated time, and error; it omits saved contract and all work queues.
- `inspect EXPERIMENT_UUID` uses `Store.read_only()` and `Store.projection()`; it
  provides useful per-experiment contract, stages, jobs, actions, reports, and
  steering, but is not a complete drain report (notably it is not a global view of
  commands, transfers, publication/outbox, project requests, or integration queue).
- `backup` uses SQLite online backup from a read-only Store and refuses a destination
  equal to the authoritative DB. It gives a consistent database copy, not evidence
  for external scheduler/action outcomes, outputs, gateway D1 queues, R2 objects, or
  filesystem workspaces. `verify` checks SQLite integrity and one experiment's
  saved evidence; it is not a drain check.
- Gateway D1 is a separate command/projection authority for pending hosted work:
  `commands` remain pending until executor receipt/ack/reject (`index.ts` executor
  command routes); published experiment projections include pending commands but
  are not a live SQLite inventory. D1/R2 are not execution authority and cannot
  replace SQLite identity reconciliation.

## Read-only inventory acceptance to add before retirement

Use an owner-authorized, freshly created online SQLite backup opened with
`mode=ro`/`Store.read_only`; never run inventory SQL against a live production
service as part of source acceptance. Verify integrity and foreign keys on the copy.
Capture the exact source commit, backup time/source identity and counts plus stable
IDs for each row below; group experiments by the JSON saved contract value, with
missing/malformed values reported separately. Do not count a queue disappearance,
terminal phase, or stale projection as proof of settlement.

1. **Experiments:** all undeleted C3 rows, with phase/hold/pause and saved identity;
   separate terminal from nonterminal, including paused and held rows. Include
   deleted rows in a separate historical group rather than dropping their linked
   work from the inventory.
2. **External/action intents:** every linked C3 `jobs` row, including submitting,
   submitted, terminal-but-unsettled, and missing/uncertain scheduler identities;
   every `agent_actions` row in pending/dispatching/running/uncertain states and any
   saved turn needing readback; every `execution_transfers` row not conclusively
   complete/failed/cancelled. Record exact intent/action/turn/transfer IDs and
   reconcile evidence, not just phase totals.
3. **Other durable work:** pending `commands` and rejected/unapplied receipts by
   origin/kind (especially create, answer, steering and cancellation); queued,
   building, or publishing `report_versions`; undelivered/retrying `outbox` events;
   active project/settings requests; and each pending/active integration request
   associated with C3. Report pending hosted D1 commands separately from SQLite
   commands. A queued command that can still target a C3 experiment blocks the
   applicable retirement action until acknowledged, refused, or otherwise settled
   with its saved receipt.
4. **Historical read surface:** retain counts/IDs for archived C3 artifacts, events,
   reports, workspaces/branches and output references; prove they remain queryable
   through saved-record readers. They are preservation checks, not drain blockers
   when no work is active.

Acceptance is **zero unresolved C3 work in categories 1–3**. Record exact per-ID
settlement; an operator note does not waive an uncertain identity. Re-run against
a fresh backup and check the hosted queue immediately before engine deletion.
New unresolved work, an unreadable authority, or uncertain external results block
retirement. These criteria are
proposed for implementation/tests against synthetic SQLite/D1 fixtures; no query
was run against production here.

## Retirement sequence

1. Complete T4.2–T4.6 source gates and resolve the owner decisions in the rollout
   and create-compatibility notes. Land create-default selection separately from
   C3 archival; do not rewrite existing contract values or reinterpret delayed
   unbound creates.
2. Add a source-level inventory/report and test its read-only behavior against
   synthetic saved C3/C4 fixtures, including uncertain intents, pending reports,
   command receipts, and gateway pending commands. Require explicit `execution_contract`
   grouping and preserve unknown/malformed values. Do not add schema or turn
   inventory into a migration or dispatch path.
3. After separately authorized default rollout, drain existing C3 work by exact
   saved identity. Then archive C3 (freeze stage mutations/advancement while keeping
   permitted exact settlement, cancellation, status and readers). Validate the
   fresh evidence above; do not use a default switch as an archive boundary.
4. Delete C3 engine writers in reviewed subsystem slices only after drain evidence:
   remove stage graph advancement/dispatch/repair, then obsolete C3-only hold,
   action and job writers. Keep historical plan/schema/artifact/report/API/export
   readers, exact settlement and cancellation as required by the rollout contract.
   Migrate shared behavioral tests to C4; retain saved-C3 fixture tests for read
   compatibility and no-duplicate settlement. No schema migration or historical
   identity rewrite is implied.
