## Method that worked

Use one worktree per slice:

```sh
git worktree add -b t4/<slice> .worktrees/<slice> main
cp -r recipes .worktrees/<slice>/
cd .worktrees/<slice> && uv sync --locked
```

The `recipes/` directory is untracked but one maintenance test needs it.

1. Delete an entry point and its callers.
2. Cascade: repeatedly delete functions in the touched modules whose names no
   longer appear anywhere in `src`. Treat the cascade with care:
   - **Never delete decorated functions.** Pydantic validators, FastAPI routes and
     properties are registered by their decorator, not called by name. This
     mistake was made once in `models.py` and reverted before commit.
   - **Generic names hide dead code.** A name-occurrence scan cannot see that
     `queue`, `apply`, `validate`, `cancel`, `prompt` or `fetch` are dead. Check
     those by their qualified uses (`early_repair.queue`, `wf.prompt(`).
   - **Same-named methods on other classes.** `self.prompt(` in conversation,
     knowledge or Autopilot is not `Workflow.prompt`.
3. Run Ruff, then the whole Python suite **per file in parallel with a timeout**.
   The plain `uv run --locked pytest -q` once hung past 30 minutes under the
   archive.

   ```sh
   S=$(mktemp -d)
   find tests -name 'test_*.py' | sort | xargs -P 12 -I{} sh -c \
     'f="{}"; n=$(echo "$f" | tr / _); timeout 600 uv run --locked pytest -q -p no:cacheprovider "$f" > '"$S"'/"$n".log 2>&1'
   cat $S/*.log | grep -hoE "[0-9]+ (passed|failed|error|errors)" | awk '{s[$2]+=$1} END{for(k in s) print k, s[k]}'
   grep -hE "^(FAILED|ERROR) " $S/*.log
   ```

   This takes about 6 minutes.
4. Classify each failure:
   - **C3-only behaviour:** delete the test.
   - **Shared behaviour that called a removed method only to prove it was inert:**
     drop that call and keep the assertions.
   - **A fixture that built C3 state through a removed writer:** seed saved state
     with test-only helpers instead (`save_snapshot`, `prepare_branch`,
     `seed_saved_contract3`). Never reintroduce production code for a test.
   Look at every failure that is *not* tagged before deleting it.
5. Rerun the full sharded suite, then commit with a one-line message,
   `refactor: <what> (T4.8)`. Add a newest-first entry to the `todo.md` log
   giving the source and test line deltas
   (`git diff --cached --numstat`). Fast-forward `main` and push.
