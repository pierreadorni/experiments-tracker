## Schema and ownership

Create `core/__init__.py` and `core/obligations.py`; do not move `store.py`.
Use the exact C2 schema: ID primary key; nullable experiment FK and project ID;
kind/target/owner/wait/state/detail; created/updated/due times; owner/state CHECKs;
`obligations_open` partial index on experiment for open rows. Keep the documented
kind vocabulary in Python. No scientific identity or content hashing.

Follow the existing transactional SQLite migration chain: from schema 23 append
this table/index and insert the next available version last in the same
transaction, using plain CREATE statements rather than masking conflicts with
IF NOT EXISTS. Update the writable and read-only supported-version checks. Do not
rewrite earlier migrations, populate obligations from guessed historic state,
change D1 or touch installation databases. Re-evaluate the next version if another
approved migration lands first; never assume 24 remains unused.

Mutation helpers take the caller's active SQLite transaction/connection and
reject `not db.in_transaction` with `RuntimeError` before writing. They do
not open/commit nested transactions or emit unrelated events themselves. The
source mutation, its obligation and its existing event/outbox write will be owned
by one transaction in T1.3b. Validate the active transaction before mutation so an
accidental standalone call cannot leave half a state transition committed.

## API semantics proposed for review

- `open(db, obligation_id, *, experiment_id=None, project_id=None, kind, target=None, owner,
  wait=None, detail=None, due_at=None)`: caller supplies a stable logical ID based
  on its saved source identity, not an inferred new dispatch identity. Insert once
  with `state='open'` and clock timestamps. Fixed fields are ID, scope, kind,
  target AND owner: any mismatch raises `ValueError` without writing, even for a
  terminal row. Changing responsibility requires abandoning the old obligation
  and opening a new ID. For an existing open row, replace wait/detail/due only
  when values differ; `None` clears a field. Preserve `created_at` and unchanged
  `updated_at`. An already satisfied/abandoned ID is returned unchanged, never
  reopened. A genuinely new obligation needs a new source/generation ID. Return
  the saved row, and document that callers must inspect its state.
- `satisfy(db, obligation_id)` / `abandon(db, obligation_id)`: transition only `open` to the specified
  terminal state; repeated same/out-of-order terminal calls leave the first saved
  terminal state and timestamps intact. Return the saved row; an unknown ID
  returns `None` without a write, allowing already-in-flight unbackfilled work to
  settle normally. T1.3b decides how callers handle that result.
- `open_for(db, *, experiment_id=None, project_id=None)`: read open rows filtered
  by supplied scope, ordered by `(created_at, id)`. No filters returns all open
  rows; both filters mean conjunction. No writes or implicit read transaction.
  Callers use an existing transaction connection or hold `store.lock`. Older
  read-only schemas without this table need compatibility handling in T1.3c.
- `derived_status(rows)`: pure selection, ignoring non-open rows and returning
  the highest-priority row as a dict, or `None` for no obligation. Do not manufacture a new `hold_reason` or change
  projections in this card. The later c card maps the selected obligation to the
  existing compatibility field after source integration is complete.
- Owner priority is exactly C2: owner > agent > backend > external. Resolve ties
  deterministically by due time (null last), created time, then ID. Keep this
  table visible as `OWNER_PRIORITY` in code/tests rather than rely on row order.
- Validate non-empty string IDs, the declared `KINDS` frozenset, owner/state,
  optional string wait/detail and valid times. Use `ValueError` for bad values or
  immutable identity conflicts, `RuntimeError` for missing caller transactions.
  Do not import `store.Conflict` and create a circular dependency. No file I/O.

Changing waits through `open`, but never the owner, is the Opus-approved design:
it supports quota/admission/timer updates on a known source without reopening
terminal work. It must not replace or continue an uncertain job/turn;
obligations track the existing record, never establish its external outcome.

## Tests and rollout evidence

Target `tests/test_iteration_obligations.py` so contract-3 fixtures are not
silently downgraded. Pure API tests need no scheduler or agent. Verify:

1. Fresh schema and upgrade preserve saved experiment/action/job/event/outbox
   identities and FK integrity. There is no checked-in historical schema-23 DB:
   seed a fresh store, drop obligations and remove version 24, explicitly label
   this a downgraded fresh fixture, then reopen. Assert no backfill, unchanged
   rows, clean `foreign_key_check`, idempotent reopen and read-only inspection.
   Also update `test_reference_outbox_migration_preserves_saved_history` to drop
   obligations and delete versions >=23 before exercising 22→23→24. Otherwise
   max version 24 skips the intended old migration and gives a false green.
2. Stable-ID replay adds no second row, changes no unchanged timestamps, cannot
   rebind immutable identity, and cannot reopen satisfied or abandoned work.
3. Mutations roll back with a caller transaction containing a source write and
   `Store.emit`; no obligation, source change, event or outbox row survives an
   injected failure. An inactive transaction is rejected before any write.
4. Scope filters, all owner/state checks and declared kinds behave as specified;
   owner priority, ties and empty selection are deterministic.
5. Terminal transitions cannot erase another recorded terminal outcome; unknown
   IDs return `None`. Fixed owner/identity mismatches fail on terminal rows too.
   Current projections/hold reasons and execution behavior remain unchanged.

Follow the phase order: after T1.2a lands, use its patchable module-level clock
without adding a `now` API parameter or new `time.time()` calls. Opus confirmed
this order and withdrew the temporary time fallback; revisit it only if the owner
explicitly reorders the cards. Target fewer than 500 changed source/test lines. Opus
estimates ~390 lines, so no split is approved unless measured scope disproves it;
never remove safety coverage to hit a size.
Run focused API/migration tests, Ruff lint/format and full Python suite. No live
state or runtime activation is part of acceptance.
