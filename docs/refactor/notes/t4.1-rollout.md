# T4.1: land the contract-4 skeleton without entering the stage engine

Baseline: Phase 3 closeout (`e56671e`). This is a source rollout, not permission
to pilot. Contract 3 remains the default; saved rows do not switch contracts
when configuration changes. T4.8 retires the old stage-engine path, not its
readers or the ability to settle saved effects.

## Three different questions

- **Archived?** After T4.1c, the active execution versions are exactly 3 and 4.
  `legacy_archive.execution_frozen()` and the startup SQLite sweep must agree,
  including for missing/null versions. The raw legacy settlement paths must
  not take contract-4 actions. `core/action_obligations.sync_action()` must not
  abandon a queued contract-4 action before the pool sees it.
- **Runs a saved stage graph?** Only 3, via `iteration.enabled()`. Do not widen
  checks for plan/prepare/title actions, stage observations and automatic repair,
  steering restart, contract-3 lifetime and report layout, or snapshot/export
  readers. `Workflow.step_control_advance()` must never call `advance()` for 4.
  Keep defense in depth on the old entry points, including for direct callers.
- **Can be displayed or commanded?** Depends on the feature, not just the
  execution version. Keep stage-only controls out of contract 4; cancel, saved
  evidence and common metadata must work. Review type checks in `Store.projection`,
  `gateway_client.py`, gateway command ingestion and `web/src` independently.
  Archive display is not a substitute for a not-yet-implemented contract-4
  feature. Revisit hosted command parity and display in T4.5 before any hosted
  pilot; source work never deploys the Worker.

## Saved identities and boundary checks

- Reuse the named worktree intent and saved checkout checks (`Workspaces.ensure_branch`,
  `checkout`, `commit_branch`). Only create contract 4 for an eligible writable Git
  project. No fallback to the main checkout or to an untracked detached workspace.
- Reuse `experiments.thread_id` and ordinary `agent_actions` with a distinct
  `research` phase. Schema 15 already permits multiple actions at the same
  phase/revision and gives each predecessor at most one continuation. Do not use
  the contract-3 evidence revision as a turn counter. Dispatch via `AgentPool`
  with the existing experiment owner key and slot accounting; do not introduce a role-local quota authority. Persist the
  exact prompt, dispatch intent and returned thread/turn identities. Recheck
  row, pause, cancellation and maintenance gates before crossing awaits that
  can dispatch. Treat an unknown start with no saved identity as uncertain.
- A persistent thread can contain repeated inputs. Do not resolve a lost response
  by accepting a matching older turn. Make the saved action identity part of the
  bounded input or establish a saved pre-dispatch turn boundary. When an exact
  turn is known, reconcile that identity. Share one result settlement path for
  live and read-back results; it must not validate a `ResearchPlan`, mutate an
  old stage, or sweep unrelated later edits into a Git commit. Give the end-of-turn
  commit an action-specific message; reuse the existing Git commit intent and
  settled event as proof after restart, even if SQLite has not yet settled the
  action. A completed commit receipt must not trigger a second `commit_branch()`
  for that action. Run idempotency and cancel/restart fault tests before activating
  the flag.
- Use obligation evidence from the current transaction when interpreting a turn
  result: no `wait` without a real condition, no `needs_owner` without an open
  research question, no `done` without a published report. Track consumed owner
  messages, job completions and other wake events by saved identity; do not use
  ambient revision churn as a wake. The initial action and every follow-up need
  a durable wake or consumed decision, not a periodic 'no running turn' test.
  Reuse `agent_wakeups`/`wakeup_obligations` where their semantics fit (T4.3).

Test plain/flagged/ineligible projects, restart with flag removed, and contract-3 regressions. Do not publish a flag that can create a row without working first-turn/reconciliation paths. |

In T4.1d, insert the first action, open its existing action obligation, and emit
its queue event in one transaction. The queue helper is not called from the
runner until dispatch and reconciliation are ready. A settled, failed, paused,
or uncertain previous turn never becomes an excuse to recreate the first turn.
Existing contract-3 continuation logic copies the previous input; T4.1f must
handle proven-absent research turns explicitly before using that or any retry
path with a new action ID.

Independent tools may be built on the protocol and v4 test fixtures before
flag activation. Job submission stays closed until T4.4 approval checks are
wired; an incomplete local skeleton is not a usable deployment. Use additive
changes only. C7 specifies a versioned notebook; first evaluate saved event
payloads for checkpoint versions rather than misusing public reports or notes.
Do not invent a new table, hold reason or configuration knob to get around an
unresolved ownership question. T4.7 still needs specific owner authorization;
T4.8 needs evidence that contract 3 has drained.
