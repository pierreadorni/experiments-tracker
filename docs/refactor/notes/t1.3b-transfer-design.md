# T1.3b transfer source replacement

2026-11-17: focused Astra read-only design review and coordinator acceptance.
This refines b7 in the approved source rollout; it does not activate derived holds
or establish historical liveness coverage. No live transport was tested.

## Saved responsibility and transport admission

Use `transfer:<execution_transfers.id>:<episode>` with backend ownership, kind
`transfer`, and the exact saved transfer ID as target. Bind scope to the saved
experiment, direction and immutable payload, never inferred current phase/evidence.

Replace the current insert-only admission: before each existing operation call,
transactionally save pending state, synchronize the obligation, and emit the
existing `state_changed` event with exact transfer identity/state. Verify parent
cancellation and saved immutable identity in this transaction. A complete-to-pending
transition proves a new episode; a pending retry preserves its episode and age.
An old complete row still executes the requested copy, preserving current behavior.
This does not create a scheduler or change copy/polling cadence.

Capture the admitted episode and immutable source tuple. Outcome transactions
verify both; old callbacks cannot settle later replay or overwrite cancellation.
Exact success satisfies, cancellation/explicit supersession abandons. Recheck
cancellation before returning success. Error text and polling timestamps do not
prove a new responsibility. CancelledError/shutdown without a known outcome leaves
pending work; no transition establishes external absence or permits job/turn retry.
Old terminal rows with no history stay without history. Unchanged pending sources
with conflicting terminal history diagnose rather than reopen.

## Exact preview replacement

New nonterminal downloads use a deterministic namespaced identity derived from
the saved job intent, analogous to terminal delivery. Preserve existing upload and
terminal identities/payloads and all historical UUIDs. At terminal-fetch admission,
explicitly supersede only that exact job's pending preview in the same transaction;
existing cancelled state plus explanatory result text records abandonment of an
obsolete optional refresh, never successful transport. Refuse stale preview
admission after terminal delivery has been admitted. Preserve remote polling,
terminal receipt checks, and existing retry cadence.

## Historical pending UUIDs

Backfill exact saved backend obligations without changing source rows. Never infer
job identity from layout/settings or merge/satisfy/retry/abandon ambiguous UUIDs.
The exact-source watchdog must issue a deterministic deduplicated existing
`engine_stuck` notice naming records without an exact resumable caller. Keep their
responsibility unresolved until established outcome or existing cancellation.
The interim watchdog excludes pending transfers and cannot supply this diagnostic.
This is a mandatory b14/d1 acceptance dependency before projection activation;
completed parents with historical pending rows may remain diagnostic.

## Ordered bounded cards

Each card must stay below 500 changed source/test lines; split further if measured
scope exceeds its budget. Use the existing episode API, one small SQLite-only
mapper, existing events and saved states; no new schema/config/reasons.

- **b7a:** replace transfer admission and outcome blocks, adding its mapper.
  Prove complete replay is pending before operation; unchanged pending retry keeps
  age; identity and stale callback conflicts refuse; source/ledger/event/outbox
  rollback is atomic. Split inert mapper from runtime wiring if needed.
- **b7b:** replace fresh preview UUID admission with exact preview identity and
  terminal supersession. Prove job isolation, failure/restart identity, precise
  supersession, stale-preview refusal and unchanged copy cadence/receipt checks.
- **b7c:** synchronize exact affected transfer rows in Store cancellation's existing
  transaction/event. Prove replay, rollback, cancellation during complete replay,
  late completion refusal and no dispatch of cancelled rows. Keep reports separate.

These necessary replacements need no new owner decision. Automatic resolution of
ambiguous historical UUIDs is outside this design. B7 is expected to be additive;
record actual counts and retain the Phase 2 net-negative requirement. The complete
remaining phase forecast is still unfunded, as described in the source-reduction
review; no hypothetical deletion credits or feature omissions are authorized.
