# T1.6a AgentPool ownership — coordinator design

Status: design approved by Opus 5.5; owner decisions 1–6 approved on 2026-11-13.
Review base `42829f4`; preceding T1 dependencies still apply. See
[approved decisions](t1-owner-decisions.md); no live activation is authorized. No new admission policy until T1.6b.

## Outcome

Wrap the existing agent instances/lane structure in an explicit reservation
registry, then route every owning operation through it while preserving current
scheduling behavior. Follow the T0.5 serialization evidence. No action/job IDs,
thread/turn IDs, action-table meaning or scientific contracts change. No new
schema/columns/tables/configuration/reasons are authorized by this card.

## Reservation model proposed for Opus's final decision

A reservation identifies `(source_table, action_id)`, role, logical owner key,
physical agent slot where a live task is assigned, and saved thread/turn identities
(which may be null before dispatch saves them).
The source tables remain `agent_actions`, `project_turns`, `autopilot_actions`;
IDs are namespaced by table, not assumed globally unique. Registry state is
reconstructed from authoritative rows, never a new execution database.

Owner keys are typed: `('experiment', eid)` for experiment stages, discussion,
title and monitor; `('project', pid)` for project research and supervision. A
project-scoped role and an experiment in that project have distinct owner keys;
this card does not start admitting such overlaps. T1.6b decides admission using
these keys and its requested same-owner exclusion.

Maintain two explicit notions: a saved logical obligation to settle a dispatched
turn, and a configured physical connection that can perform readback/callbacks.
A completed asyncio task is not proof of a settled durable action. Logical
reservations derive from source rows plus live in-memory claims, without hooks
into every state writer. Dispatching/running/uncertain rows retain owner/action
exclusion. Received results retain logical owner exclusion but no connection;
existing controllers apply them without a new turn or loss of saved results.
Current role busy-state sets remain unchanged in a.

## Coordinator implementation plan

1. Add a small `engine/agents.py` or narrowly named pool module holding the registry
   and lookup helpers. Keep lanes/agents as existing transport owners; don't clone
   another CodexAgent or move all dispatch code yet. One live turn per agent, and
   no ownership release merely because a task returned or raised.
2. Claim the reservation synchronously, before `create_task` or the first awaited
   external call. The durable source action/dispatch intent must already exist.
   On task completion, re-read its source row: release a claim if terminal or
   still pending (never sent); retain logical ownership if dispatching/running/
   uncertain. This requires proving each adapter persists dispatch intent before
   begin. Never release merely because a task returned, and never pin a never-sent
   pending task forever. Received rows keep owner exclusion without a connection.
3. Preserve every current global exclusion/admission guard in this card. Registry
   lookups replace ambiguous ownership routing, not scheduling policy. Experiment
   multi-lane concurrency must remain as before; research/supervisor/conversation
   still follow their existing serial admission until T1.6b.
4. Route session/begin/finish/readback/interrupt/reply through registry lookups.
   A connection is one App Server process, not the reusable CodexAgent object.
   Add an in-memory start counter; capture `(slot, start counter)` for request,
   activity and quota callbacks at receipt, together with reservation generation.
   Never read a later mutable counter and attribute an old event to a new process.
   Validate saved thread/turn identities, remove the global research fallback,
   and fail closed on unmatched requests (including missing identity where
   correlation is unprovable). Late activity cannot attach to a successor.
   Supervisor requests have no supported handler today and remain fail-closed.
   Use existing error/uncertainty handling, no new hold vocabulary.
5. Pending RPC replies are connection-bound. Keep an in-memory map from answer
   ID to `(slot, start counter, reservation)`. Answer only through that same live
   process and reservation, exactly once; otherwise expire the request as today.
   Restart or reconnect never replays an obsolete rpc_id. Cover experiments,
   titles/monitors/discussion, Autopilot and fail-closed supervisor requests.
   No new persisted pending-request fields or slot columns.
6. Rebuild reservations at the beginning of Workflow.start, before connect_agent
   can refresh quota and reach interruption paths, and before any admission.
   Retain original thread/turn/action IDs and recover by existing readback logic.
   Slot directory differences currently affect logs (`CodexAgent.__init__`), not
   a separately configured authentication home; nevertheless unreadable threads
   remain uncertain, never evidence of absence or permission for a new turn.
7. Session-count shrink retains every logical reservation and owner. Reconstructed
   reservations have no live connection; only a live task on a live connection
   consumes a physical slot in a. Existing readback RPCs can use a configured
   connection without starting another turn. Do not add capacity debt or a global
   admission block here: whether unresolved remote turns count against b's turn
   capacity is an explicit T1.6b design/owner decision, not assumed runtime behavior.
   Never create hidden extra servers or change durable IDs during readback.
8. Quota interruptions, owner pauses, reconciliation and shutdown enumerate all
   occupied reservations and route through their owning connection, not the primary
   `Workflow.agent`. Expiring a callback or cancelling a task cannot declare its
   external turn absent. Set closing/stop admission before closing role tasks or
   connections; test this deliberate reordering of the existing shutdown, which
   currently sets closing after research/supervisor close. Drain known tasks and
   preserve uncertainty through existing source states.
9. Keep existing role-specific result application and transactional events/outbox.
   Registry reconstruction reads source state; it does not rewrite archived rows,
   import credentials or query a live managed account during tests.

## Opus-selected bounded split

Split by concern, not by role: the unsafe research request fallback is shared and
must not be half-converted across role-specific commits.

- **T1.6a-1 (~350 lines):** derived registry plus shadow claims at all seven
  admission sites across the six roles (agent stage, two title sites, monitor,
  conversation, research, supervisor); startup reconstruction, release rules and
  tests. No routing or scheduling changes.
- **T1.6a-2 (~450 lines):** process start counter; request/activity/answer routing
  for every role; remove research fallback and fail closed when unmatched.
- **T1.6a-3 (~400 lines):** quota interruption, readback/reconciliation, shutdown,
  and shrink/restart tests. Close each transport once, preserve unknown outcomes.

Each must measure under 500 changed source/test lines and keep the suite green.
Use no new persistent slot column just to simplify reconstruction. If any seam
cannot be made safe within these boundaries, stop and revise the design rather
than claim a partially populated registry is authoritative.

## Verification

Tests use fake agents with distinct connection identities and event queues:

- Existing two-experiment lane concurrency still reaches two running turns with
  two sessions; one slot and existing project-role policy remain unchanged.
- Every request/activity/reply/interrupt/readback reaches only the reserved agent
  and source action; late notifications cannot attach to a new reservation.
- Saved dispatching/running/uncertain actions from all three tables reconstruct
  before admission. Ended in-memory tasks do not free uncertain reservations.
- Restart plus session shrink retains all exact IDs and logical reservations,
  respects the configured number of live connections, and never duplicates a
  turn. Do not claim remote unresolved turns stopped with their old process.
- Expired saved RPCs are not replayed; quota/shutdown cover every occupied slot,
  and each transport is closed once after its owned work is handled.

Assert actual saved rows and fake external-call counts, not only pool bookkeeping.
Run targeted role/lane recovery tests, Ruff and full Python suite. T1.6c supplies
broader mixed-role scenarios after b; a does not claim live runtime acceptance.

## Opus 5.5 final design decision

Fresh-context run `3b116f01-d891-471e-9010-1dd62152212e` decided **REVISE (approve
after corrections)**. The corrections and concern-based split are incorporated
above. Follow-up run `b4fa49ae-e8bc-4c92-9ab9-71efca240926` gave the final
verdict **APPROVE**, with no remaining design corrections. Unresolved remote-turn
liveness/capacity belongs to b, not a. Routing changes deliberately fix wrong-lane answers and
unsafe research fallback; they are not scheduling-policy changes. Implementation
is permitted after its dependencies under the approved owner process decisions.
