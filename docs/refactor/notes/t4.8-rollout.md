# T4.8: switch, drain, then retire

T4.7 accepted an isolated assisted local CPU run. It did not authorize changing
an existing owner, default, remote account, or gateway. Do not count an accepted
pilot or a green CI run as evidence that contract 3 has drained.

## 1. Finish the source gates before changing the default

- **T4.2/T4.3 remote jobs:** stage a pinned commit against the existing remote
  adapter and its saved execution context. Reuse its polling cadence and exact
  intent reconciliation. Persist the successful terminal accounting and finish the
  exact output transfer before a result-ready wake. Failed/cancelled jobs must
  still wake once, without promising outputs. A pending transfer stays backend work;
  neither retrying a transfer nor seeing healthy compute should spend inference.
  Test lost submission, accounting lag, transfer interruption, and restarts with
  the remote adapter scripted. Do not route C4 jobs through C3 stage advancement.
  See the [bounded remote source cards](t4.3-remote-rollout.md).
- **T4.4 Autopilot:** `review_experiment_plan` currently requires a C3 plan revision;
  it is not C4 approval proof. Reuse the saved member/run/policy and calendar at
  the C4 approval and dispatch boundaries, with an exact objective/request binding.
  Keep human approval proof separate; a model cannot grant or expand its own
  envelope. Test a policy revision, defer/pause, and a changed objective between
  authorization and dispatch. Keep GPUs refused until the saved-intent reservation
  and exact scheduler accounting are wired at the C4 boundary.
  **Owner decision:** activating Autopilot delegates approval of new objectives
  for linked research experiments to the Autopilot orchestrator. It does not grant
  the experiment agent approval authority. The approval binds the exact request
  and objective to the current run and policy; pause, deferral and backend token
  and compute limits still apply. Manual experiments keep exact owner approval.
  Test an autonomous CPU run through a ready report without a human answer, plus
  refusal of stale approvals and dispatch outside current authority.
- **T4.5/T4.6:** check owner controls against the same C4 projection locally and
  through the Worker, including replay, steering, pause/resume and checkpoint
  privacy. Complete remaining C12 scenarios. Run the locked source checks and a
  C4 synthetic demo with no model, scheduler account or production services.
  The dispatcher-to-report acceptance is runnable with
  `uv run --locked pytest -q tests/test_research_synthetic_demo.py`.
  This does not change the existing C3 CLI demo.

## 2. Switch creation only; keep both readers and engines

Change the new-experiment selection without rewriting any saved execution contract.
Define which existing create inputs have C4 equivalents (including reference
snapshots, shared checkouts, and remote execution settings); refuse unsupported
inputs clearly rather than silently changing their meaning. Upgrade the demo and
project defaults in source first. Verify that old jobs/actions, delayed commands,
reports, exports and artifacts still work with their original contract. The default
switch ships separately from retirement and needs owner authorization to install.
See [creation compatibility](t4.8-create-compat.md) for delayed hosted requests,
legacy clients, and the cross-version rollout order.

## 3. Verify drain on the actual installation; retire separately

See the [drain evidence map](t4.8-drain-evidence.md) for the saved identities and
read-only evidence required before retirement.

Under the owner-authorized upgrade procedure, inspect read-only inventory by saved
contract. Check nonterminal C3 experiments (including paused and held), live or
uncertain actions/job intents, pending transfer/report/publication and integration
work, and pending commands. An unresolved identity is not drained merely because
its queue entry is gone. Obtain fresh evidence before retiring C3; do not cancel or
relabel work just to make the count zero.

Archive C3 through C10, preserving reports, artifacts, events and historical exports.
Keep exact settlement and authorized cancellation for old in-flight identities,
without entering the stage graph. Before deleting the stage engine, migrate tests
that still exercise shared behavior to C4, and prove archived reads plus exact
settlement against a saved C3 fixture. Review the deletion by subsystem; it is not
a migration that rewrites historical identities. Installation, restarts, and
hosting changes remain owner-authorized and separate from source publication.
