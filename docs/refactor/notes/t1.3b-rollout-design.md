## Identity and responsibilities

Keep immutable owners and terminal IDs. Identify responsibility episodes as
`source-type:<saved-id>:<episode>`, allocating episodes inside real source
transition transactions from existing obligation history. Episode zero starts
tracking. Unchanged source replay retains its episode/timestamps. A genuine
responsibility change abandons the old episode and opens the next; never invent
an episode just because `open()` returns a terminal row. Repeated
running/uncertain/running transitions must not reopen terminal identities.

Actions belong to backend/admission while pending, backend/reconcile while
dispatching or uncertain, and agent while running with an exact saved turn.
Jobs belong to backend during admission/uncertain submission and external after
an exact scheduler identity is saved. Agent pseudo-jobs are not Slurm jobs.
Transfers and publication remain backend-owned. Questions and reviews belong
to the owner. Fulfillment satisfies; cancellation, failure and supersession
abandon. Reconciliation never establishes external absence or permits retry.

Persist a backend `reconcile` obligation targeting the experiment identity for
its execution lifetime: advance the saved experiment. Keep it through source
handoffs, with wait pointing to the saved blocking source or `none`; close on
terminal/archive. Do not refresh its age on every tick or unrelated event.
Its ordinary displayed hold is `None`, not a new reason. The watchdog must
check its concrete dependency or whether unblocked advancement is serviced.

## Existing state and coverage

Backfill in fixed-size keyset batches, re-reading each candidate inside the
write transaction and using the same mapping helpers as source writers. Derive
only from saved active identities/states. Never change source state, contact an
external system or infer success. Conflicting terminal obligation history is
diagnostic, not permission to reopen or manufacture another episode. No
migration-time historical inventory.

Frozen legacy has no advancement obligation; track only allowed exact-identity
settlement, saved publication and cancellation. Preserve its archive hold and
readers. Timers use the saved wakeup ID/due time; queueing its saved action
closes the timer in that transaction. Overdue timers require backend inspection,
never duplicate dispatch.

The invariant is experiment-scoped. Independent `project_turns` and
`autopilot_actions` need explicit later project-scope cards; do not claim they
are covered as experiment actions. Report publication tracks version readiness,
keyed by saved request/version, not remote delivery. Artifact delivery and
outbox acknowledgements retain their own durable identities and retry semantics.

## Projection and completion boundary

Astra recommends deriving displayed holds first while retaining operational
persisted reasons during migration. Explicitly allowlist source/wait mappings
to existing reasons; ordinary running work maps to `None`. Never derive a reason
from arbitrary detail text or owner priority alone. Cover every operational
hold before activation. Preserve terminal/archive presentation. If the table
is absent, return historical projection unchanged without writes. Read source
and obligation state under one transaction/lock.

Coordinator amendment: retaining operational writes is an intermediate safety
step, **not completion of T1.3c**. The todo also requires replacing direct writes
by call-site group. Remeasure and design those bounded groups before claiming
c complete; do not silently defer a stated T1 requirement beyond this goal.

Activate obligation watchdog only after source coverage and backfill. Check
each exact source, owner notice, persisted timer and backend progress using
the existing interval. Reuse deduplicated `engine_stuck` notices; watchdog
never dispatches, retries or repairs source state. No new schema/config/reasons.

## Action integration implementation constraints (coordinator, 2026-11-15)

For b2–b4, share a small SQLite-only action mapping helper rather than copying
owner/episode decisions into every writer. Capture the old saved action row
inside the caller transaction before its SQL mutation; read the resulting row
in that same transaction before updating obligations and emitting the existing
event. A pre-await snapshot or a state-name comparison alone is insufficient:
saving an exact thread/turn can change responsibility without changing a state
label. Set source_transition only for a proven change in the relevant saved
state/identity; metadata-only replays cannot manufacture episodes.

Terminal callbacks use latest_episode to find existing work, verify their exact
source identity/state, and satisfy or abandon only an open episode. Missing
history stays missing for old terminal records. An active source conflicting
with terminal history is diagnostic, not an implicit new generation. Map running
without both saved IDs to backend reconciliation, never a known live agent turn.
Pending frozen non-discussion execution cannot acquire admission work; allowed
exact settlement and completed-parent discussions retain their existing paths.

These constraints preserve source state/intent/turn authority. Helpers track it;
they never retry, resolve external absence, change an action or authorize dispatch.
Keep hold projection unchanged until the full source/backfill gate. Remeasure the
post-h source writers before delegating bounded implementation cards.
