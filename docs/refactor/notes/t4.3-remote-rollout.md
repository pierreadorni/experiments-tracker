# T4.2/T4.3: remote job source gates

Contract 4 is still local-only. The submission gate refuses other contexts and
`Workflow.observe_jobs()` skips them for C4. Do not remove either guard as a
standalone change: C4 currently marks scheduler success complete and wakes the
agent in one transaction, while the existing remote `fetch()` expects a C3
stage receipt and stage-indexed `expected_outputs` that C4 never writes.

## Proposed output boundary

Use the single `result_file` named by C7, not a C3 stage manifest or a directory
transfer. For an initial remote CPU slice, require one bounded relative result
file at submission, saved in the exact job request; local submissions without
that field keep their existing behavior. Download only that declared file into
the exact saved local attempt. Never let a later model turn choose a new remote
source path. Use the existing regular-file and size bounds, temporary staging,
and atomic placement; reject symlinks, traversal, directories, and a missing
file. Validate the metrics at `register_result`, not in the transfer loop.
Retain existing transport checks where applicable without adding scientific
hashes, inventories, or a final validation barrier.

## Implementation order

1. **Declare and bind the file (T4.2, landed).** The C7 field shares result-path
   validation and binds registration to the exact declaration. Omission or null
   preserves the old saved request, including defaulted resources. Tests cover
   altered replays and wrong attempt or path. Remote submission stays closed.
2. **Record and deliver exact success (T4.3).** Route saved C4 remote jobs through
   the existing adapter's saved settings and polling cadence before resolving
   missing IDs. Record exact terminal accounting before transfer. A job with
   successful accounting stays unresolved until its own download completes;
   use the existing transfer row and obligation, not a new hold reason. Resume
   from saved accounting on restart and reuse completed download evidence if
   the owner stopped before settling the job. Commit `complete` and the
   debounced wake together. Failed and cancelled jobs wake once without
   waiting for a result. Healthy jobs and pending downloads don't wake.
3. **Stage and dispatch (T4.2).** Reuse the remote transport for the pinned
   commit, argv, and saved route; don't call the C3 stage-output worker as if
   it handled C4. Save the exact remote intent before `sbatch`, and adopt it
   on a lost response instead of sending again. Open the gate only after the
   scripted scenario proves exact approval, accounting lag, transfer
   interruption, restart, and exactly one submission and result-ready wake.

No change to the creation default, remote account, live owner, or archive
boundary is part of these cards.
