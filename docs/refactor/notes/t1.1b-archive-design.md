# T1.1b archive boundary and implementation cards

Design investigation against `8899608`, 2026-11-14. No live resources used.
This applies owner decision 6 and the completed migration gate (disposition §19).
It does not authorize live activation. Source/test sizes below are hard ceilings;
documentation is counted separately. Coordinator review remains required.

## Decisions

- Legacy means `contract.get("execution_contract") != 3`, including an absent
  field. Archive only nondeleted, nonterminal experiments. Keep their saved phase;
  set the named `legacy_contract_archived` hold. Use existing `required_decision`
  inbox kind, deterministic text explaining that execution is archived and cancel
  remains available. Hold, notice, events and outbox commit atomically.
- Sweep at the very beginning of `Workflow.start`, before any await, and at the
  beginning of every `tick`, before research/control callbacks or cancellations.
  Store migrations have already finished when Workflow is constructed. Do not put
  archival into schema migration or read-only Store opening.
- `advance` must return for every non-3 contract, independently of hold. Automatic
  failed-action recovery and repair also skip non-3 contracts: otherwise terminal
  legacy failures can resurrect after the sweep. Archive is not cancellation.
- Observe saved external identities; never dispatch, continue a turn, apply a
  result to stages, register newly completed scientific outputs, or change archive
  phase/hold. Record action results and scheduler terminal states/accounting even
  when those results would fail current/legacy output schemas. Unknown identity
  remains unknown. No archive transition proves external absence.
- Already queued report versions still pass through `advance_reports` unchanged:
  build/verify/register/publish from saved evidence; its existing report failure
  handling changes the report, not the archived experiment. Do not call `publish`
  to finish the legacy state machine or create a new final report.
- Cancellation retains `Store.cancel_experiment` and `process_cancellations`:
  exact intent adoption, exact cancellation, terminal accounting, uncertain-turn
  hold and background-check drainage. Cancellation owns the phase/hold thereafter.
- Keep explicit **terminal failed legacy** `reconcile_outputs` recovery and its
  invalid-output/symlink/rollback tests until the card deleting that legacy body.
  Likewise preserve completed-record cleanup until h.5, and completed historical
  discussion/report/export readers. Do not blanket-disable legacy readers or
  manual terminal recovery with a generic Store mutation ban.
- Retire `test_restart_rechecks_saved_terminal_job_without_resubmission[True]`
  with activation. Its nonterminal completion/seal path becomes unreachable.
  Replace it with static late-settlement coverage: corrupted/missing checkpoint
  bytes are never read; exact saved job settles, stage and artifact rows stay
  unchanged, no submission/inference occurs, archive phase/hold persist. Retain
  `failed_directory_run` and retained terminal recovery tests. Delete its
  `checking_directory_run` fixture only if the replacement does not use it.

## Boundary details

Use a small `legacy_archive.py` module, imported by workflow/steering/controller
and (for predicates only) store. Keep it free of imports from Store/Workflow:
stdlib plus `clock` and `TerminalTurnError` suffice; helpers receive workflow/store.
Define two pure predicates, rather than checking recipe IDs or only a hold:
`execution_frozen(exp)` is `contract.get("execution_contract") != 3`;
`archive_active(exp)` additionally requires nondeleted and phase outside
`complete/failed/cancelled`. The sweep's SQL mirrors these predicates. Runtime
execution-entry guards use the first; hold preservation and nonterminal control
guards use the second. `Store.update` protects an already installed archive hold,
so the archival primitive can install that hold in its own transaction.

Completed historical `discuss:*` actions stay on their existing reader workflow,
including newly requested discussions on completed archived parents. Never route
them through a blanket legacy dispatch ban. Generic execution dispatch is distinct
from `Conversation.dispatch`. For titles/monitors block archived nonterminal work;
do not accidentally disable completed-parent reader capabilities. The settlement
pass may cover all legacy **non-discussion** actions, preserving terminal phase/hold
too; skip cancelled experiments because the cancellation pass owns interruption
and settlement there. No legacy action settlement authorizes stage advancement.

`observe_jobs` needs a separate settlement path before remote fetch, progress and
TensorBoard reads, manifest parsing, validation/sealing or stage registration.
Coordinator implementation review correction (2026-11-14): this automatic path
must handle every nondeleted, noncancelled frozen legacy experiment, including
terminal failed/complete records with outstanding submitted jobs. Restricting it
to `archive_active` leaves those jobs entering the old scientific validation body.
The helper preserves their saved terminal phase/hold; explicit terminal manual
`reconcile_outputs`/`reconcile_agent_output` remain unchanged. Only the archive
sweep and owner-facing archive hold are restricted to nonterminal experiments.
Use `scheduler_for(exp, job)` and its saved routing. Respect remote polling cadence.
Reconcile a missing job ID from the exact intent; no match leaves it unresolved.
Persist an adopted ID and `job_reconciled` atomically. Observe that ID, send the
observation through existing budget accounting, and transactionally save scheduler
state, exit code, observation/start/end times and job state with `job_observed`.
`COMPLETED` plus known successful exit settles `complete`; known bad terminal
outcome settles `failed`; accounting-pending/unknown exit stays unsettled. Job
failure never calls `fail` or updates stages. Observation exceptions record an
error on the job without changing archive hold or inventing terminal state.
Do not add a new remote result-transfer requirement: archived job settlement
does not need scientific output downloads. Preserve existing transfer records.

Drain existing `output_checks` and `evidence_checks` for archived experiments,
consume exceptions and discard results. Do not cancel a filesystem thread and
assume it stopped. Drain only existing work; never start a new legacy check.
The observation helper must not await a still-running check before recording
scheduler facts. Cancellation and close must still see outstanding checks.

Saved research/title/monitor actions need a settlement-only pass before the
maintenance `blocked()` return in tick, just like job observation. Skip actions
owned by a live lane task. For unowned `dispatching/running/uncertain` actions with
both saved IDs, read that exact turn: save raw completed result, known
`TerminalTurnError` failure, or uncertainty on unreadable/nonterminal result.
Missing IDs stay unresolved. Never run result validators, `agent_stage`, or
`continue_action` from this pass. Existing `_action_state` supplies transactional
events and idempotence. Preserve normal accounting reconciliation.

`reconcile_action` keeps all exact-identity and missing-turn prompt-proof checks.
For legacy non-discussion actions, after verified readback, persist raw result/identity
and event without stage validation or clearing phase/hold. Its completed replay
must stay idempotent. Do not weaken current-contract reconciliation. Explicit
terminal failed legacy `reconcile_agent_output`, like `reconcile_outputs`, remains
until its legacy-body removal; it is not the automatic settlement path.

The following bypasses need explicit guards, not just a filtered advance loop:

| Location | Required boundary |
|---|---|
| `Workflow.start` pending-request expiry | Expire obsolete RPC as today, preserve archive hold. |
| `tick` pending-request replies | Never reply/continue an archived turn. |
| `hold_active_action`, `_request`, dispatch exception paths | Preserve archive phase/hold while saving action interruption/error/request identity. |
| `agent_stage`, `_submit_prepared_stage`, `dispatch`, `dispatch_title`, `publish` | Fresh guard at entry and after awaits before submission/session/turn or stage mutation; no new legacy execution. |
| `dispatch` after `begin` / `finish` | Save actual returned turn ID/result even if archival/cancellation happened while awaiting. Do not discard evidence. |
| `advance_title`, `title_applicable` | Archived pending work cannot dispatch or apply a completed title; exact live turn settles via archive pass. |
| `Controller.advance`, `Controller.call` | No new monitor/wakeup, continuation or mutating tool call for archived experiment; status reads remain usable. Exact turns settle separately. |
| `apply_planning_steering`, `process_restarts` | Do not rewrite a plan, cancel for replacement, create replacement or clear archive hold. Retain saved steering. |
| `recover_terminal_actions`, `repair_failed_experiments` | Skip all non-3 execution; terminal legacy records remain terminal automatically. |
| `Store.command` | Archived nonterminal execution commands (`answer`, `plan_review`, `steer`, action other than cancel) reject through existing `Conflict`, before consuming steering/queuing work. Preserve completed historical discussion/presentation. |
| `Store.update` | For already archive-held nonterminal records, preserve phase/hold against late callbacks while allowing observed metadata/errors; explicit cancel uses its existing transaction. This is a safeguard, not a substitute for guarding raw SQL. |
| watchdog | Add archive hold to ignored owner holds; no engine-stuck notice. |

Contract fields do not normally mutate during a turn. Still test delayed callbacks
with a pre-existing task and saved archive hold; direct SQL is not protected by
`Store.update`. An entry guard alone cannot protect a suspended dispatch. Avoid
adding global stage bans, config switches, new tables/reasons, or shutdown-based
identity conclusions.

## Ordered cards

1. **b-P1, S <150, inert Store primitive.** `store.py` and new
   `tests/test_legacy_archive.py`: add `archive_legacy_experiments()` with no runtime
   caller. One transaction updates nonterminal non-3 rows and inserts existing-kind
   notice/events only when needed. Tests: missing/1/2 versus 3, terminal untouched,
   repeated call same revision/events/inbox, injected emit failure rolls back
   hold/notice/outbox. Do not modify any job/action/stage identity or pending RPC.
2. **b-P2, M <500 (target <300), inert job settlement.** New small archive module
   plus its focused tests; implement exact job observation described above, no
   normal-runtime caller yet. Parameterized completed/bad/accounting/unknown-exit,
   lost-submit exact adoption/no match, observe error and remote routing/polling;
   assert unchanged stage/artifact/phase/hold and no fetch/validate/submit.
3. **b-P3, M <500 (target <350), inert action settlement.** Separate
   `legacy_archive_actions.py` plus tests permits independent implementation without
   concurrent module edits; share the pure predicates at integration.
   implement the unowned action pass and existing-check drainage without activation.
   Cover completed/terminal-failed/unreadable/missing IDs, live lane exclusion,
   repeated pass, and unfinished/done/failed checks. No continuations or validators.
4. **b-P4, M <500, atomic activation and guard set.** `workflow.py`, `store.py`,
   `steering.py`, `controller.py`, `watchdog.py`, archive module and focused tests.
   Wire sweep/job/action helpers, all guards in the table, and archived exact
   operator readback. Replace restart sealed-byte test. Must be one coherent
   activation commit: first call of sweep cannot land without every dispatch,
   observation and continuation boundary. Use existing cancellation/report tests
   and compact archive variants to avoid duplicating whole fixtures.
5. **b-A, S <150, acceptance-only additions if needed.** Additional targeted tests
   for queued report success/failure, cancellation unresolved→settled, maintenance
   blocked settlement, RPC expiry/reply suppression and rollback/restart behavior.
   Prefer placing essential assertions in P4; this card does not excuse a known
   unsafe activation. Full suite and synthetic demo acceptance precede publication.

S-per-card sketch: exact settlement and cross-path activation with meaningful
tests cannot honestly fit <150 lines each. No card may reach 500 changed source

activation. This changes task sizing only, not owner-approved archive semantics.
